Compact filters, and totals as a row

The totals row. In all four options it sits at the foot of the table (and sticks there when scrolling), counting how many members are in each column, as the Campaigns Brief does for a party row. The per-member Total column is gone.

A — Totals row doubles as the placement filter (my recommendation)

Click a gradient heading, or its total, to filter to that column. That removes the placement control entirely: the numbers you were going to read anyway become the control. Party drops to one dropdown. The whole filter apparatus is then a single line.

B — Pill row

Both filters as togglable pills on one wrapping line, counts inline. Keeps multi-select, which the dropdown loses, and every option stays visible. Costs two lines on a narrow screen; parties beyond the big four need an "other" pill or they run away with it.

C — Filters inside the header

Spreadsheet convention: a filter row under the headings, so the controls live in the column they filter and cost no vertical space above the table. Familiar to anyone who uses Excel. Slightly cramped, and the placement filter has nowhere natural to sit since it spans five columns.

D — Search does everything

One box, no filter controls at all: typing "labour" narrows by party, "++" by placement, "SW1A 1AA" by postcode. Smallest possible footprint and nothing to learn if you guess right — but it hides what is filterable, and you cannot see the party breakdown without typing. Good as an addition to A, weak on its own.

What I would build

A, with D's cleverness folded into the search box. Making the totals row the placement filter is the move that actually saves space, because it deletes a control rather than shrinking one: the numbers a campaigner reads anyway become the thing they click. Party then fits in one dropdown, and the search box can additionally understand a party name or a placement typed in, so the fast path exists without advertising itself.

One behaviour worth deciding: should the totals row show the counts for everyone (a constant 296/2/24/0/327, useful as context) or for the filtered set (which changes as you filter, useful as an answer)? I would show the filtered counts with the full-set figure beside it in the label, so you always see both: "Totals — 9 shown of 649".
